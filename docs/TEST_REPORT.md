## 音声同梱後の確認
- 全90本（合計6,380,799バイト）、359チャンク。Chromeのオフライン状態で90日すべてを復号し、各教材の終端が音声長内にあること、すべてのチャンクに非ゼロの音声信号があることを検査した。音声内容の人による全件聴取は行っていない。
- FFmpegで0.8秒のテスト音をAAC/M4Aに符号化し、Chromeの通常のファイル読込操作で復号・保存できた。WAV・MP3も検証済み。実機ごとのコーデック差は引き続き確認が必要。
- Chromeの同一プロファイルで実際にMP3をファイル入力から取り込み、ブラウザプロセスを終了して起動し直した。実績画面から開け、IndexedDBに残った音声のバイト数が元ファイルと一致した。
- Windows版Playwright WebKit（375 × 812、タッチ設定）でも旧履歴、Day 90、ワーカー更新、新版の再表示を確認。配信元を全件503にして新しいタブを開き、キャッシュから起動した。このWebKitにはマイクとWeb AudioのAPIがなく、非対応時の案内までを確認。iPhone Safariの実メディア処理の検証は残る。
- 初回のHTTP 204はAzureのCORS事前要求の値。APIを模した診断値はテストの一時プロファイルだけで使用した。ソースのキー・秘密鍵の代表パターンの走査は一致0件。
- 原稿を開いた場合、反復・速度変更・チャンク再生などを使った場合は「練習条件」で履歴に残す。初回の標準条件の集計とは分ける。
