## 教材・音声の実査

- Day 1の引き継ぎでは「数字の誤り」と「列見出しの確認」を区別する。Day 7は照会・電話の増減から同一顧客の移行を断定できない理由を述べる。Day 43は16%と1.6%の訂正、Day 60は未提出分を含む暫定判断、Day 90はグループ合計を先に公表する条件と追質問への応答を扱う。前半の分節音、中盤の句境界・訂正強勢、後半の業務上の言い換えという進行がある。後半の即興課題はSpeaking 75の学習者にも練習目的を持たせやすい。
- 各期30日の原稿の平均語数は33.3、36.1、40.4語。音声は各9.5〜14.2秒、期間別の概算速度は184、185、188語/分。Listening 61への負荷は、長時間の情報保持よりも短い発話から条件や機能語を聞き取ることにある。毎日1問の日本語三択には偶然正解があり、正答率単独をVERSANT換算する根拠はない。固定文の練習効果、難易度を等化していない初見文、即興の伝達力を分けて解釈する。
- /ɡrəʊθ/ の語末、非R音性の quarter と後続母音、receipt の黙字と第二音節強勢、record の名詞・動詞の強勢、本文の levelled・labour・per cent などを点検した。語末の摩擦や焦点位置を変えて意味の違いを伝える指示は実用的。広い英国式IPAと地域話者の実際の母音には幅がある。低い語スコアだけから /θ/ の誤りと診断する実装は見当たらない。
- 全90 MP3（6,380,799バイト）をChromeのオフライン状態で復号し、全359区間に音声信号があることと末尾時刻を確認。別に全ファイルをローカルの faster-whisper tiny.en で、正解原稿を渡さずに英語文字起こしした。英文を小文字・英数字トークンに分け、順序を保つ一致ブロックを数えると3,291語中3,143語が一致。これは発音の正答率でもWERでもない。Day 43の “sixteen per cent / one point six per cent” は “16% / 1.6%” に正規化された。Day 24の “Unless” やDay 78の “eastbound” では認識が崩れ、ASRだけで合成の誤読とは判定できない。総音声長は1,063.5秒。
- 生成コード、現物のモデルSHA-256、構成の `language.code=en_GB` と `espeak.voice=en-gb-x-rp`、公開モデルカードの英国北部単一話者指定を照合。英国英語の合成モデルを用いたという説明と整合する。MP3単体にはモデルを証明する署名はなく、全90本の地域アクセント、強勢、イントネーションを人が聴いて認定したものではない。[モデルカード](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_GB/northern_english_male/medium/MODEL_CARD)
- 60分は精聴10・発音15・追唱20・即興10・振り返り5分。15分は3・6・5・1分。通常日の短縮版は実施しやすい。定点日の6分は固定・初見の収録と一点の聞き返しを優先すれば成立し得る。初日の権限設定、Azure登録、全区間の採点・再録までを含む所要時間は実測していない。60分版は約12秒の素材を何度も読むため、追唱20分の後半は指定の再録比較・原稿なしの発話を行うことに意味がある。

## 発音診断、無料枠、データ

- RESTの送信先を地域別のSpeechホストに固定し、言語はen-GB、音声は16 kHz・mono・PCM16。Azureが返す精度、流暢性、完全性、語別の読み落とし等を解析する。en-GBは発音評価対応。音素に名称がない場合は番号と取得値を表示し、強勢やイントネーションをAzureの点数として補完しない。MicrosoftのProsody評価はen-US限定。APIの利用可否と、本人のF0・地域・キーで採点が完了するかは別々に確認する必要がある。[言語対応](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=pronunciation-assessment)・[ロケール別評価](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment)・[短時間REST](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short)
- `lib/audio.mjs` は40 msフレームの自己相関から有声部のF0と中央値基準の半音曲線を推定し、内部の約200 ms以上の低音量区間を記録する。録音長と原稿語数からの参考WPMは実装済み。実発話の語数、自由発話WPM、自動音節整列、語強勢・イントネーションの正誤判定は未実装。正弦波と無音のテストは計算上の挙動を確認し、雑音下の人声に対する測定精度は担保しない。
- 1端末内では採点・認識をIndexedDBで原子的に予約し、月240分。失敗も予約に残し、自動再送をしない。キー誤り、429、ネットワーク失敗は練習を続けられるエラー扱い。F0の公表枠は標準リアルタイム認識月5時間。価格レベルは本人のチェックで、契約・複数端末・他アプリの使用量はPortalが基準。PlusやOpenAI APIを呼ぶコードはなく、付属音声、録音、音響解析、履歴、復習はAzureなしで動作する。[Azure料金](https://azure.microsoft.com/en-us/pricing/details/speech/)
- PR先端までの到達可能な6コミットの配布ツリーを調べた。78種類の非MP3・非PNGの固有blobを対象に、秘密鍵ヘッダー、代表的なAPIトークン、独立した32桁hex、メール形式を検索し、該当なし。テストのキーはfixture。教材は架空の業務例で、公開ツリーに利用者録音は見つからなかった。これは網羅的な秘密・個人情報検出ではない。
- `index.html` のCSPは外部スクリプトとインラインスクリプトを許可せず、`lib/ui.mjs`、診断、履歴の表示で文字列をエスケープする。キーは既定でメモリ、明示選択した場合だけ端末保存。バックアップの設定は開始日・コースに限定。同一GitHub Pagesオリジンの別プロジェクトにもブラウザの保存領域は共有されるので、所有者が信頼するコードだけを同一オリジンで配信する前提。復元は版・IDと録音対応を検証後に一取引で反映し、同一IDはバックアップ値で上書きする。
- 付属MP3はPiperで生成しておりAzure音声の再配布に依存しない。`docs/AUDIO.md` にモデル、原コーパスの権利者、合成・加工方法、CC BY-SA 4.0の表示がある。確認した一次資料との矛盾は見当たらない。個人が追加する音声の利用権は個別に確認する。[OpenSLR 83](https://www.openslr.org/83/)・[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)
